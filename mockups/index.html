로또 · 상생 궤도(번호를 고르는 계산)

  1. 1–45를 원 둘레에 놓고, 칸의 오행은 하도 끝자리로 정한다(1·6 수, 2·7 화, 3·8 목, 4·9 금, 5·0 토 · 오행마다 9칸).
  2. 출발점은 오늘 일진의 60갑자 순번을 45로 나눈 나머지 칸. 시주를 알면 시간·시지만큼 먼저 걸어 출발점을 옮긴다.
  3. 원국의 년·월·일 여섯 글자로 한 번씩 걷고, 걸을 때마다 공 하나를 놓는다. 걸음 수 = 글자 번호(천간 1–10, 지지 1–12) + 오늘 일진의 같은 쪽 글자 번호.
  4. 지금 칸과 글자의 오행이 상극이면 반시계, 상생이거나 같으면 시계 방향.
  5. 기신 칸이나 이미 뽑힌 칸이면 같은 방향으로 한 칸씩 더 간다.

시뮬레이션(무작위 원국 20만 개)

  • 번호별 빈도: 평균의 0.96–1.03배. 서로 다른 조합 96.5%. 다음 날과 겹치는 번호 평균 1.05개, 완전히 같은 날 0.01%.
  • 오늘 글자를 걸음 수에 더하지 않고 출발점만 바꾸면 다음 날과 똑같은 날이 4.9%라 버렸다(비켜 가기 때문에 궤적이 합쳐진다).

사주 값은 lib/saju에서 타입만 지워 옮긴 shared/saju/(node mockups/tools/build-saju.mjs)로 계산해 앱과 같습니다. 로또 엔진은 shared/lotto.js, 공 색은 ?balls=lotto|element|mono 또는 상단바의 스위치로 바꿔 봅니다.

언어 전환 · 통과 기준

  1. 전환이 만든 애니메이션 중 컴포지터로 못 간 것 0(트레이스 Animation의 compositeFailed)
  2. 첫 애니메이션 프레임 뒤 Layout·Paint가 매 프레임 나지 않음(애니메이션을 시작하는 프레임의 1회만 허용)
  3. 20ms 넘는 프레임 15% 이하, 한 번에 두 프레임 이상 밀리지 않음(최대 간격 50ms 미만)
  4. 동작 줄이기: 움직이는 것 없이 바로 바뀜(앱은 모든 전환 애니메이션이 0ms)
  5. 끝난 상태: 갈 언어로 새로 연 화면과 본문 글자가 같고, 남은 view-transition-name·가로 넘침·JS 오류 0

고른 이유와 버린 아이디어

움직이는 것은 누른 칩 하나와 글자의 짧은 빠짐·들어옴뿐이라 매번 봐도 질리지 않고, 틀이 그대로라 "같은 페이지, 말만 바뀜"이 분명합니다. 동전의 앞뒷면과 운으로 정해지는 회전 수가 브랜드의 재미를 맡습니다.

  • 슬롯 릴(글자 덩어리마다 원통이 굴러 다섯 박자로 멈춤): 재미는 크지만 다발로 움직여 "한 번에 한 가지" 규칙과 부딪히고, 이름 박자 계산이 무겁다.
  • 카드 뒤집기(누른 곳에서 물결처럼 소개·타일이 뒤집힘): 게임 페이지는 스테이지 한 장이 화면 전체라 맞지 않는다.
  • 클로버 셔터(로고의 네 잎이 화면을 덮었다 걷힘): 반응은 가장 빠르지만 언어 전환마다 화면 전체를 0.6초 덮어 무겁다.
  • 글자 스크램블·타자기: 매 프레임 글자를 바꿔 레이아웃·페인트가 난다.
  • 블러 크로스페이드: filter: blur는 컴포지터로 못 간다.
  • 원형 리빌·복권 긁기: clip-path/마스크 애니메이션은 메인 스레드에서 돈다.
  • 좌우 슬라이드: 같은 내용인데 다른 페이지로 간 듯 보이고 운의 재미가 없다.
  • 공항 출발판: 위·아래 반쪽을 따로 접으려면 스냅샷을 둘로 잘라야 해서 뷰 전환으로 못 한다.
  • 로고 한 바퀴·주사위·원판·경마 레인·사다리·로또 공: 누른 곳과 반응이 끊기거나, 산만하거나, 다시 보면 지루하다.

측정에서 알게 된 것

  • 합성 속성만 써도 뷰 전환은 애니메이션이 시작·끝날 때 메인 스레드에서 스타일을 다시 계산하고, 그 비용이 이름 붙인 요소 수에 비례한다(이름 1/10/30/60개 → 0.6/5.7/8.7/16.9ms, 4배 감속). 글자는 덩어리로 묶는다.
  • 크롬은 그룹 키프레임의 from/to 크기를 다른 정밀도로 적는다(29.1094px/29.109px). React의 "크기 그대로" 판정이 빗나가 width/height 애니메이션(비합성)이 남을 수 있어, 동전은 onShare에서 직접 지운다.
  • 화면 전체를 섞는 크로스페이드는 GPU 없는 환경에서 프레임을 크게 놓쳤다. 바뀌는 글자 덩어리에만 이름을 붙여 해결했다.
  • 전환이 도는 중에 다른 언어를 누르면 그 이동의 커밋이 앞 전환 뒤로 밀린다. 그사이 요청이 끼면(프리페치 전, 개발 서버) 전환 타입이 사라져 언어 전환 대신 페이지 간 모프가 나왔다. 앱은 전환을 하나씩 차례로 돌리고 마지막으로 누른 언어만 이어서 바꾼다.
  • 브라우저는 전환 스냅샷을 뜨는 동안(시작부터 애니메이션 준비까지, 약 50ms) 클릭을 <html>로 보낸다. 앱은 전환을 시작할 때 잰 칩 자리로 그 클릭을 돌려준다.
